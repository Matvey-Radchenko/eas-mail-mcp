# Инструкция для ИИ-агента

Эта инструкция настраивает локальный EAS Mail MCP на macOS 14+ или Windows 11
x64 через публичный npm-пакет. Сервер запускается самим MCP-клиентом и не требует
daemon.

Пользовательская инструкция: [Установка EAS Mail MCP](installation.ru.md).
Полный справочник по setup и ручным конфигам:
[Getting started](getting-started.md).

## Границы безопасности

- Не просите пользователя отправлять пароль в чат, файл, `.env` или аргумент
  команды. Передайте ему интерактивный terminal для скрытого prompt.
- Профиль не содержит credentials, но может содержать непубличные endpoint
  metadata и публичный корпоративный сертификат. Не загружайте его во внешние
  сервисы.
- Не отключайте TLS, проверку сертификатов или quarantine и не меняйте EAS URL.
- Оставьте write tools выключенными, если пользователь явно не попросил иначе.

## Установка и настройка

1. Установите стабильный релиз и проверьте выбранный нативный бинарь:

   ```bash
   npm install -g eas-mail-mcp
   eas-mail-mcp --version
   eas-mail-mcp native-path
   ```

2. Запустите единый мастер:

   ```bash
   eas-mail-mcp setup
   ```

   Если оператор передал `team-profile.toml`, выберите импорт в мастере или
   сначала выполните `eas-mail-mcp profile import ./team-profile.toml`. Для
   `realm_username` пользователь вводит короткий логин без ручного `REALM\`.

3. Передайте terminal пользователю на время ввода email, логина и скрытого
   пароля. Мастер сам позволяет добавить следующие аккаунты, а затем предлагает
   настроить найденные Codex, Claude Code и OpenCode с backup/rollback.

4. Проверьте итог:

   ```bash
   eas-mail-mcp account list
   eas-mail-mcp profile list
   eas-mail-mcp doctor
   ```

5. Попросите пользователя перезапустить MCP-клиент. После перезапуска проверьте
   `accounts_list` и `folders_list`. Не вызывайте mail/calendar tools, если
   пользователь просил только проверить подключение.

Повторный `eas-mail-mcp setup` открывает меню добавления и исправления аккаунтов,
обновления пароля, write-доступа, профилей, клиентов и диагностики. Сетевые ошибки исправляйте
проверкой нужной сети/VPN; не ослабляйте TLS. `AUTH_REQUIRED` означает проблему
credentials, а `ACCESS_DENIED` — запрет EAS или отсутствие allowlist.
