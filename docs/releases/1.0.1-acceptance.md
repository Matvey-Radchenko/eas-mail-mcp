# 1.0.1 release acceptance

- Status: candidate; publication gates are pending
- Release type: stable calendar bug-fix patch
- Functional source: `62e56c8b7613357a2e6a3fe6cef21650bd2b002a`

## Scope

- Zero-duration events and recurring occurrences no longer break calendar reads.
  Creation and editing retain positive-duration validation.
- Forwarded recurring invitations can be answered through mail references.
  Attendance replies preserve organizer and occurrence identity and do not
  require support for unrelated full-item edit metadata.
- Online meeting attendee updates preserve server-managed connection metadata
  and unchanged exceptions. Roster-only notifications target affected people;
  content or schedule changes reach all current attendees. Unsafe disabled
  exception reminder rewrites fail before mutation.

The MCP/CLI public contract and journal schema are unchanged. Updating does not
require account or password reconfiguration.

## Evidence and boundaries

- The functional source passed 552 local tests, coverage thresholds, formatting,
  Clippy, rustdoc, contract, dependency, and public-data audits, plus all four
  required CI jobs. The release commit must pass its own checks before staging.
- Two real forwarded-series acceptance paths succeeded, one in Calendar and one
  through forwarded mail, across the two configured accounts. Read-back and
  cross-process UUID replay passed. See
  [forwarded-series acceptance](../acceptance/forwarded-series-responses.md).
- The original online-series scenario passed synthetic backend and scripted EAS
  transport checks, including retained exceptions and targeted notifications.
  This scenario has not been repeated against a live Exchange server. See
  [online-meeting acceptance](../acceptance/online-meeting-updates.md).
- Platform checks distinguish native CI from Wine/Whisky. Neither establishes
  live Windows Exchange, VPN, or Credential Manager acceptance. Fresh OS-profile
  credential provisioning remains unverified; no existing credentials are reset
  for this patch.

## Publication gates

required exact-SHA CI, stage IDs, downloaded archive hashes, isolated upgrade and
platform checks, read-only live checks, performance, and the staged-binary soak
before approving packages. Prior version-specific soak exceptions do not apply.

Approve the three native packages first, then the root package. Verify registry
installation, package integrity and provenance, align `latest` and `next`, and
only then create the matching source tag and GitHub release.
