# 0.5.1 release acceptance

- Status: release candidate
- Release type: stable patch release
- npm dist-tags: `latest`, then `next` to the same version

## Scope

Version `0.5.1` fixes calendar mutations discovered during the first live
personal-series validation after `0.5.0`:

- event references retain the UID and are rebound to the active EAS 14.1 Sync
  session before mutation;
- recurring writes accept empty server-managed fields that carry no data;
- an empty Reminder is represented as an explicit clear instead of unsupported
  input;
- Calendar Delete requests explicitly use permanent-delete semantics.

The MCP and CLI contracts remain unchanged at 23 tools.

- [x] Formatting, Clippy with denied warnings, rustdoc, file-size limits,
  schemas, tests, coverage, dependency, license, secret, and public-audit gates

## Live evidence

- [x] On one configured EAS account, a short personal recurring series was
  created, one occurrence was changed, the selected-and-following tail was
  split, both resulting series were verified, and all test items were removed.
- [x] On a second configured EAS account, a short personal recurring series was
  created, listed as occurrences, deleted, and confirmed absent.
- [x] Final cleanup checks found no test events on either account.

## Accepted limitations

- Recurring invitations, updates, cancellation, and responses with a live
  recipient remain unverified.
- Windows x64 is accepted through CI packaging and existing Wine coverage; no
  physical Windows acceptance run is repeated for this patch.
- No physical Intel Mac or new soak run is required for this stateless patch.

These are residual risks rather than passing results. Ambiguous or partial
writes must not be retried with a new idempotency key.

## Publication gate

The exact release commit must remain clean, pass npm pack/install and public
artifact audits, then build and stage all four npm tarballs in CI. Approve the
three native packages first and the root package last. After registry smoke,
move `next` to `0.5.1` and create source-only tag/release `v0.5.1`.
