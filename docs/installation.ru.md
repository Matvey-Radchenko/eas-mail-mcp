# Установка EAS Mail MCP

Основной сценарий установки на macOS и Windows: npm-пакет и интерактивный
мастер. Вводить пароль в MCP-конфиг, `.env` или аргументы команды не нужно.

Полная англоязычная версия инструкции: [Getting started](getting-started.md).

## Требования

- macOS 14+ на Apple Silicon или Intel либо Windows 11 x64;
- Node.js 18+ и npm;
- Exchange ActiveSync 14.1 с Basic Auth поверх TLS;
- доступ к необходимой корпоративной сети/VPN и доверенному CA.

Windows ARM64 и Linux не поддерживаются. Windows `.exe` выпускается без
Authenticode-подписи; macOS использует ad-hoc-подпись без Developer ID notarization.
Границы CI, Wine/Whisky и проверки реальных устройств описаны в
[матрице совместимости](compatibility.md).

## Установка

```bash
npm install -g eas-mail-mcp@latest
eas-mail-mcp --version
eas-mail-mcp native-path
```

Npm выбирает нативный пакет под ОС и архитектуру и не запускает `install` или
`postinstall` scripts. Node.js нужен для установки и CLI-launcher, но MCP-клиент
подключается напрямую к Rust-бинарнику, поэтому Node.js не остаётся в рабочем
процессе.

Не отключайте optional dependencies npm: через них устанавливается нативный
бинарник. Если команда после установки не найдена, откройте новый терминал и
проверьте `PATH`. `npm prefix -g` показывает npm prefix; команды находятся в
его подкаталоге `bin` на macOS и прямо в prefix на Windows.

## Мастер настройки

```bash
eas-mail-mcp setup
```

На первом запуске мастер:

1. Импортирует готовый endpoint-профиль или создаёт его вручную.
2. Запрашивает email, логин в формате профиля и скрытый пароль.
3. Проверяет TLS, авторизацию, EAS 14.1, Provision policy и FolderSync.
4. Сохраняет аккаунт и данные системного хранилища секретов только после успешной проверки.
5. Отдельно предлагает включить write-доступ, который по умолчанию выключен.
6. Позволяет добавить следующие аккаунты.
7. Настраивает найденные Codex, Claude Code и OpenCode с backup/rollback.
8. Запускает `doctor`; локальные идентификаторы аккаунтов видны в обычном выводе.

При ошибке можно исправить профиль, email, логин или пароль и повторить
проверку. Неуспешные credentials не сохраняются.

Повторный `eas-mail-mcp setup` открывает меню управления: добавить или исправить
аккаунт, обновить пароль, изменить write-доступ, управлять профилями, настроить
клиентов или запустить диагностику.

## Профиль сервера

Профиль содержит адрес EAS-сервера, разрешённые почтовые домены, формат логина и
режим TLS trust. В нём нет пароля, Device ID, policy key или данных конкретного
аккаунта.

Если коллега или администратор выдал готовый профиль:

```bash
eas-mail-mcp profile validate ./team-profile.toml
eas-mail-mcp profile import ./team-profile.toml
eas-mail-mcp setup
```

Пример профиля schema v2:

```toml
schema_version = 2
bundle_version = "operator-1"

[[profiles]]
id = "work"
display_name = "Work Mail"
host = "mail.example.com"
email_domains = ["example.com"]
device_id_length = 16

[profiles.identity]
mode = "realm_username"
realm = "EXAMPLE"
username_hint = "Short corporate login"

[profiles.trust]
mode = "system"
```

Для `realm_username` пользователь вводит короткий логин, а мастер сам сохраняет
его в виде `REALM\username`. Поведение shell и экранирование обратного слеша на
этот сценарий не влияют. Полная схема, включая профиль с публичным CA:
[Runtime profiles](runtime-profiles.md).

Создать профиль вручную можно через `eas-mail-mcp profile add`.

## Несколько аккаунтов

Добавить второй и последующие аккаунты проще всего через повторный `setup`.
Доступен и отдельный интерактивный сценарий:

```bash
eas-mail-mcp account add
```

Команды обслуживания:

```bash
eas-mail-mcp account list
eas-mail-mcp account update-password <account-id>
eas-mail-mcp account set-writes <account-id> on
eas-mail-mcp account set-writes <account-id> off
eas-mail-mcp account remove <account-id>
```

Write-доступ общий для поддерживаемых почтовых и календарных изменений этого
аккаунта, включая отправку писем и настройку автоответов. После его
включения операция выполняется сразу, когда агент вызывает write tool: отдельной
формы подтверждения внутри MCP нет.

Для автоматизации сохраняются полные флаги и `--password-stdin`. Неполная
non-TTY команда возвращает `INTERACTIVE_REQUIRED`. Пароль нельзя передавать в
аргументах, `.env`, профиле или MCP-конфиге.

## Подключение MCP-клиентов

Мастер предлагает настроить обнаруженные клиенты. Те же действия можно
выполнить отдельно:

```bash
eas-mail-mcp client configure codex
eas-mail-mcp client configure claude
eas-mail-mcp client configure opencode
```

Конфигуратор создаёт backup, записывает прямой путь к Rust-бинарнику и делает
rollback при ошибке. После настройки перезапустите клиент: изменение файла не
закрывает уже запущенные stdio-сессии.

Для ручной настройки получите путь:

```bash
eas-mail-mcp native-path
```

Примеры TOML/JSON-конфигов Codex, Claude Code и OpenCode находятся в разделе
[Manual configuration](getting-started.md#manual-configuration).

## Проверка

```bash
eas-mail-mcp profile list
eas-mail-mcp account list
eas-mail-mcp doctor --check
```

После перезапуска клиента безопасная MCP-проверка состоит из read-only tools
`accounts_status` и `folders_list`. `accounts_list` показывает конфигурацию,
а `accounts_status` заново проверяет каждый аккаунт и сохраняет отдельные ошибки.
Не используйте отправку письма или изменение
календаря как smoke-тест без явного запроса владельца аккаунта.

Почтой и календарём можно пользоваться и напрямую из терминала без ИИ-агента:

```bash
eas-mail-mcp --human mail list --limit 10
eas-mail-mcp --human calendar agenda \
  --from 2026-08-24 --to 2026-08-30 --time-zone Europe/Belgrade
```

Эквивалентный пример для Windows PowerShell:

```powershell
eas-mail-mcp --human mail list --limit 10
eas-mail-mcp --human calendar agenda `
  --from 2026-08-24 --to 2026-08-30 --time-zone Europe/Belgrade
```

Полный список команд, JSON-режим, переносимые ссылки и подтверждение write:
[CLI reference](cli.md).

Каждое активное MCP-подключение запускает один `eas-mail-mcp serve`. Поэтому при
нескольких чатах или задачах процессов может быть несколько. Они должны
завершаться вместе со своими stdio-сессиями.

## Где хранятся данные

```text
macOS config: ~/Library/Application Support/EAS Mail MCP
macOS cache:  ~/Library/Caches/EAS Mail MCP
Windows:      %LOCALAPPDATA%\EAS Mail MCP
```

Пароли, Device IDs, policy state и HMAC key журнала идемпотентности хранятся в
macOS Keychain или Windows Credential Manager. Почтовой или календарной базы нет. SQLite содержит только
метаданные write-операций без тем, адресатов и текста. Вложения попадают во
временный кэш только после отдельного скачивания.

Вложения становятся доступными для очистки через 24 часа. Очистка выполняется
при запуске runtime и перед следующим скачиванием, фонового таймера нет.
`cache status` показывает размер и число просроченных файлов. Для немедленной
очистки используйте `cache clear --account work` или `cache clear --yes` для
всех аккаунтов. Журнал, настройки и секреты при этом сохраняются.

Ограничение Windows: все аккаунты используют одну запись Credential
Manager размером не более 2 560 байт в UTF-16. В лимит входят пароли и служебные
данные всех аккаунтов, поэтому фиксированного допустимого числа аккаунтов нет.
При переполнении появится `STORAGE_ERROR` с сообщением о размере; прежняя запись
останется неизменной. Удалите неиспользуемые аккаунты через CLI перед повтором.
Разблокировка хранилища не поможет; не сокращайте пароли ради обхода лимита.
К macOS Keychain это ограничение не относится.

## Обновление и восстановление

Запишите текущую версию и разберите неопределённые write-операции. Закройте
MCP-клиенты. Для восстановления можно сохранить приватную копию каталога
конфигурации, пока процессы остановлены. Не выгружайте пароли в обычный файл.

```bash
eas-mail-mcp --version
npm install -g eas-mail-mcp@latest
eas-mail-mcp --version
eas-mail-mcp doctor --check
```

Профили и аккаунты сохраняются. Версия 1.0 обновляет журнал транзакционно, с
сохранением UUID и результатов прежних операций. Перезапустите MCP-клиенты и
проверьте `accounts_status`. При изменении npm prefix или пути к бинарнику
повторите `client configure` для нужных клиентов.

Если обновление неработоспособно, выключите writes, сохраните безопасный отчёт
и следуйте [инструкции восстановления](../SUPPORT.md). Возврат данных 1.0 к
версии 0.5.1 не прошёл приёмку: установка старого бинарника не означает
проверенный откат данных. Старые версии не предоставляют новые инструменты и
всю новую информацию журнала. Сохраните текущий журнал и credentials на время
диагностики. Не восстанавливайте старую копию журнала после новых отправок:
так теряется защита от повторения операций. Если версия не принимает более
новую схему, верните новую версию вместо удаления базы.

Начиная с 1.0 историю можно проверить без подключения к Exchange:

```bash
eas-mail-mcp operation list --status unknown
eas-mail-mcp operation list --status partial
eas-mail-mcp operation get <operation-uuid>
```

Для `pending`, `partial` или `unknown` сначала проверьте состояние на сервере.
Повтор с исходным UUID возвращает сохранённый результат без новой отправки;
новый UUID не является безопасным способом восстановить неизвестный результат.

Для завершённых `succeeded` и `failed` операций UUID защищён от повторного
выполнения 90 дней после последнего сохранённого изменения. После этого срока
запуск программы может удалить завершённую запись; старый UUID тогда может
выполниться заново. Обычная очистка не удаляет `pending`, `unknown` и `partial`.
Очистка по политике RemoteWipe выполняется отдельно. Сохраняйте актуальный
журнал при разборе неопределённых операций; очистка кэша не меняет защиту UUID.

## Отключение и удаление

Сначала закройте MCP-клиенты и удалите управляемые записи у тех клиентов,
которыми пользуетесь:

```bash
eas-mail-mcp client unconfigure codex
eas-mail-mcp client unconfigure claude
eas-mail-mcp client unconfigure opencode
```

Чужие настройки клиентов сохраняются. Перезапустите клиенты: изменение конфига
само по себе не завершает уже работающий сервер.

Удаление только пакета с сохранением настройки для повторной установки:

```bash
npm uninstall -g eas-mail-mcp
```

Для полного удаления до удаления CLI разберите неопределённые операции,
очистите скачанные вложения и удалите нужные аккаунты и неиспользуемые профили:

```bash
eas-mail-mcp cache clear --yes
eas-mail-mcp account list
eas-mail-mcp account remove <account-id>
eas-mail-mcp profile list
eas-mail-mcp profile remove <unused-profile-id> --yes
```

Повторите удаление для каждого нужного аккаунта/профиля, затем удалите npm-пакет.
`account remove` удаляет запись аккаунта и его credentials, но сохраняет журнал,
кэш и общую запись хранилища с HMAC key. Оно не отменяет письма, события или
автоответы на Exchange.

После остановки всех процессов вручную проверьте оставшиеся данные:

- каталоги конфигурации и кэша из раздела выше, включая журнал и lock-файлы;
- `Client Config Backups` в каталоге конфигурации: резервные копии могут содержать
  настройки других интеграций, не публикуйте их;
- общую запись macOS Keychain: service `eas-mail-mcp`, account `secrets-v1`,
  либо Windows Generic Credential `secrets-v1.eas-mail-mcp`;
- экспортированные профили и отчёты в выбранных вами местах.

Удаляйте общую запись секретов только при удалении всех аккаунтов. Журнал
удаляйте после проверки незавершённых операций, осознанно прекращая возможность
их восстановления. Полная таблица данных:
[Unconfigure and uninstall](getting-started.md#unconfigure-and-uninstall).

Для обращения в поддержку сохраните отдельный безопасный отчёт:

```bash
eas-mail-mcp doctor --check --report ./support-report.json
```

В нём нет идентификаторов аккаунтов, адресов, доменов, путей, usernames,
credentials и исходных текстов ошибок. Обычный вывод `doctor` не равноценен
этому отчёту. Правила и приватный канал для уязвимостей: [Support](../SUPPORT.md).

## Частые ошибки

| Ошибка | Что проверить |
| --- | --- |
| `AUTH_REQUIRED` | Credentials отсутствуют, OS-хранилище заблокировано/недоступно или Exchange отверг логин. Разблокируйте хранилище либо обновите пароль и проверьте формат email/логина |
| Native package missing | Переустановите пакет с включёнными optional dependencies npm; launcher укажет нужный нативный пакет |
| `ACCESS_DENIED` | EAS-доступ, device policy или allowlist у администратора |
| `CONFIG_INVALID` | `profile validate`; не ослабляйте правила endpoint или TLS |
| `INTERACTIVE_REQUIRED` | Запустите TTY-мастер либо передайте все automation-флаги и `--password-stdin` |
| TLS/network error | Нужную сеть/VPN и утверждённый CA; не отключайте проверку TLS |
| MCP не виден | Повторите `client configure`, перезапустите клиент и запустите `doctor` |
| `FEATURE_UNAVAILABLE` | Сервер не предоставляет нужную команду или идентификаторы; проверьте ограничения функции |
| `OUTCOME_UNKNOWN` / `partial` | Сохраните UUID, посмотрите `operation get` и проверьте состояние Exchange; не повторяйте с новым UUID вслепую |

## Ограничения

Поддерживаются только HTTPS, EAS 14.1, Basic Auth и стандартный путь
`/Microsoft-Server-ActiveSync`. OAuth, Microsoft Graph, IMAP, нестандартный
endpoint, redirects, TLS bypass и подмена DeviceType не поддерживаются.
Повторяющиеся встречи можно изменять с явной областью `series`, `occurrence`
или `following`; ответы поддерживают `series` и `occurrence`. Неподдерживаемые
структуры recurrence блокируют запись. Разделение серии не атомарно на сервере.

Почтовый поиск и цепочки имеют лимиты и признак неполного покрытия; отсутствие
результата при неполном покрытии не доказывает отсутствие письма. Некоторые
серверы не возвращают изменяемые идентификаторы для результата поиска: письмо
можно читать, но для мутации нужна ссылка из `mail list`. Удаление означает
перенос в корзину, без permanent delete. Автоответ проверяется повторным чтением,
поскольку политика может ограничить внешние аудитории. Точность free/busy — 30 минут.

Для флажков, категорий и статуса прочтения требуется подготовленная сессия папки.
В отдельном процессе CLI добавьте `--sync-folder` к `mail set-flag`,
`mail set-categories`, `mail mark-read` или соответствующему `mail batch`.
Этот флаг явно разрешает загрузить письма выбранной папки в пределах серверной
политики перед изменением; он не делает результат поиска изменяемым. Используйте
ссылку из `mail list`. Если письмо изменилось во время загрузки, команда вернёт
`SYNC_STALE`: получите свежую ссылку и снова проверьте действие.
